## iOS task

Establish and cite the current iOS telemetry carried on the test record before building: which device and version fields are attached, where each value is read from, at what point in the flow they are captured, and how they travel with the record to the backend. Record that as the baseline, then attach the same field set to the QACR test record, reading each value from the platform rather than from a build-time constant where the baseline does so.

## Android task

Record that as the baseline, then attach the same field set to the QACR test record, reading each value from the platform rather than from a build-time constant where the baseline does so.

## Acceptance criteria

1. **automatable** — A completed test record carries every device and version field named in the cited baseline, with no field absent and none renamed (FR-PLT-008).
2. **automatable** — Each field's value is read from the platform at the point in the flow the baseline captures it (FR-PLT-008).
3. **automatable** — The record delivered to the backend carries the telemetry fields in the shape the backend contract expects (FR-PLT-008).
4. **manual** — On two devices of different model and OS version, the records received differ in exactly the fields that describe the device and the build. Requires two physical devices and backend-side inspection.
