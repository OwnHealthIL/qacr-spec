## iOS task

Fetch run-time configuration at start-up and hold it in one place. Wire providers to request the bootstrap key names that APIKeys.Bootstrap.Response already declares, and widen the persisted settings struct beyond its three fields to carry them, keeping build-time defaults on the values that have one — a value the server does not supply keeps its default, in the shape of `self.x = data.x ?? self.x`. Decode the response through a typed Decodable schema rather than per-field casts over a dictionary, and treat a decode failure as a configuration state that has not completed.

Drive the server environment from build configuration in place of the hardcoded `.staging` value.

Gate the start on configuration state: while the settings state is loading or unknown, the start is refused and routed to its blocking state, in the shape of `canStartFlow()`.

Attach the configuration set in force to the data a completed test sends to the backend (departure D2), so the record carries the configuration it ran under.

For FR-CFG-004 (server-side enforcement of demonstration behaviour, milestone 1) and FR-CFG-006 (the application's response to a configured blocked state), establish and cite the current iOS behaviour first, then build to it.

## Android task

Fetch run-time configuration at start-up and hold it in state. Restore `Actions.UpdateInitConfiguration` so the fetched configuration is written into state, give `Actions.UpdateInitializationFlowState` a dispatch site and a reducer case, and drive the nine-state `InitializationFlowState` through the fetch so its value reflects where configuration stands. Keep build-time defaults on the values that have one — a value the server does not supply keeps its default.

Gate the start on that state: `FAILED` refuses the start with the fatal-settings outcome, and any value other than `DONE` refuses it with the no-response outcome, each routed to its blocking state.

Attach the configuration set in force to the data a completed test sends to the backend (departure D2), so the record carries the configuration it ran under.

For FR-CFG-004 (server-side enforcement of demonstration behaviour, milestone 1) and FR-CFG-006 (the application's response to a configured blocked state), establish and cite the current Android behaviour first, then build to it.

## Acceptance criteria

1. **automatable** — Configuration is fetched at start-up and every value the response supplies reaches the consumer that reads it (FR-CFG-001).
2. **automatable** — Configuration state moves through its declared values as the fetch progresses, and its terminal value distinguishes a completed fetch from a failed one (FR-CFG-001).
3. **automatable** — While configuration has not completed, the start is refused and the no-response blocking state is presented (FR-CFG-002).
4. **automatable** — When configuration fails, the start is refused and the fatal-settings blocking state is presented (FR-CFG-002).
5. **automatable** — A value the response does not supply keeps its build-time default where one exists, and the app starts a test using that default (FR-CFG-002).
6. **automatable** — A malformed or undecodable configuration response leaves configuration in a not-completed state, refuses the start, and does not crash (FR-CFG-002).
7. **automatable** — A completed test's data carries the configuration set that was in force when it ran (FR-CFG-003, departure D2).
8. **automatable** — After a successful test, real or demonstration, the user is told before a new one starts and is not blocked from starting it (FR-CFG-004).
9. **automatable** — With the backend supplying a blocked state in configuration, the app presents that block and refuses the start (FR-CFG-006).
10. **manual** — The configuration attached to a completed test is received and stored intact by the backend. Requires backend-side inspection of a real submission (FR-CFG-003).
11. **manual** — FR-CFG-004 and FR-CFG-006 behave as the current product does, against the baseline established and cited in the platform task. Requires side-by-side observation of the shipped product.
